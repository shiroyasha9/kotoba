# kotoba

Native macOS menu-bar dictation: tap a chord, speak, tap again, the cloud transcript is pasted in about one second. Read `docs/spec.md` before feature work: it holds the agreed decisions, gates and phases. `docs/research/` holds the evidence behind them.

## Commands

- `make check`: the bar for every change (swift-format lint, `swiftlint --strict`, xcodebuild, every registered view's layout checks (window fit, cut-off pill text, the pills' VoiceOver buttons) with no image (`make view-checks`, about 6 s), `swift test`, then KotobaCore's tests once more in slow mode (`make test-slow`, about 4 s)). SwiftLint also checks UI text (CODING_STANDARDS.md "User-facing text" 3, 4, 5, 8, 13, 14: "…" not "...", keys as symbols (⌃⌥⌘, not "Control-Option-Command"), no internal terms, no " - " between phrases, curly ’ “ ” not ' or \", no "we", "please", "enable"/"disable"/"toggle" or interjections) on UI-building lines in `App/` and every string in `App/StatusText.swift`. Done means green. When other agents share the checkout, run `make check AGENT=<your name>`: your own xcodebuild and SwiftPM build folders, so parallel runs do not collide.
- `make privacy` (first step of `make check`): the repo is public, so `scripts/privacy.sh` fails on a home folder or session temp path, an email address other than an `example.com`/`.org`/`.net` or GitHub noreply one, an API key, or a private key block in a tracked file. Use placeholders (`<runbooks>/`, `me@example.com`, `sk-or-test`). Personal data, bench audio and ops notes stay outside git (the runbooks folder, or `docs/progress.md`, which is ignored).
- `make build` writes the app the owner runs (`build/DerivedData`); `make check` builds into `build/DerivedData-check`, so it never replaces a running bundle.
- `make format FILES="a.swift b.swift"`: fixes formatting in place in your own files. Plain `make format` rewrites the whole tree, other agents' files too; use it only when you work alone.
- `make lint-files FILES="a.swift b.swift"`: swift-format lint and swiftlint on your files only. While other agents edit, report your files' result; a red `make check` from another agent's file in progress is theirs to fix, not yours to report.
- `make snapshots`: builds like `make check`, then renders every view registered in `App/Snapshots.swift` (indicator states at each anchor, Settings panes) to `build/snapshots/<name>-light.png` and `-dark.png`. Each view is laid out in a window that is never ordered on screen and captured as the window server draws it (ScreenCaptureKit, `App/SnapshotCapture.swift`): real Liquid Glass, vibrancy and text on glass, every window as the active app's key window (colored traffic lights, accent list selection and "on" switches). Nothing shows on screen. It needs Screen Recording for the terminal app that runs `make`; without it the run stops and names that app (ask the owner to turn it on). After a UI change, look at your PNGs with the Read tool. To add views, write a `static func snapshots() -> [Snapshot]` next to your view and add one line to `Snapshots.registry`; a view that floats over other apps (a pill) sets `floatsOverDesktop`, so its glass shows over a fixed desktop backdrop. Two limits remain: the main window's sidebar draws edge to edge, not as the inset floating panel (it seems to need the desktop behind the window), and a toolbar that changes after the window is built can show its glass mid-animation, so the `window-switch-*` snapshots run their layout check and write no image. The run ends every Core Animation animation that has an end before it captures (a control's own transition, such as the input level gauge's 250 ms first value), so an image never shows one midway. Small run-to-run noise is expected: a spinner's phase in some pills and text antialiasing in the Fix Last Dictation windows. A blank or odd image is a bug until you prove otherwise (2026-10-15: a "blank" Settings image was a real layout bug the owner then hit). Register whole windows, not only panes; `windowSnapshot` fails the run when content does not fit the window.
- `make readme-images`: renders the README's screenshots (`Pane.readmeSnapshots`, the whole window content with sample data, the release's name and icon) in macOS's default blue accent and copies them to `docs/images/`. Look at them before you commit.
- `make test`: all package tests (KotobaCore, KotobaProviders, KotobaStorage), each package under a hard limit (`TEST_LIMIT`, default 120 s; `scripts/timeout.pl` kills the whole process group). `FILTER=<test name>` runs one test. A test that hangs is a bug: give every awaited fake event a bound, never wait on the wall clock. A test never sets a time limit either: on a machine busy with other agents' builds it fails while the code is fine. Count the work instead (lint `no_wall_clock_in_tests`; CODING_STANDARDS.md "Tests").
- `make test-slow`: KotobaCore's tests with every fake port call slowed (`KOTOBA_TEST_SLOW`, 1,000 yields first), as on a busy machine. A test that passes only because the pipeline's tasks ran before its next step fails here. `make check` runs it.
- `make timing`: the wall-clock checks `make test` leaves out (the `TimingTests` suites in KotobaCore and KotobaStorage: the History pane's reads, Activity, retention and the ledger fill on 10,000 dictations, the Polish diff, the dictionary's replacements), each printed with its limit. Run it on an idle machine after a change to one of those paths.
- `make gen`: regenerates `Kotoba.xcodeproj` from `project.yml`. Edit `project.yml`; the project, `App/Info.plist` and `App/Kotoba.entitlements` are generated.
- `make window-memory`: the main window's footprint at launch, open on every pane and after close (offscreen, sample data, the allocator mode the app gets from `LSEnvironment`). A change to the window or to what it loads reports these numbers.
- `make latency-log` (`DEV=1`, `LAST=2d`, `FROM=<saved log>`): the latency gate and the stop path split from the unified log, with no database read (`make latency RUN=1` reads the app database and needs the owner's go). `bun run latency` in `bench/` probes the route's server time (`docs/research/latency-pass.md`).
- `make stop-probe` (`RUNS=2000`, `BASE=<git ref>`, `ROUNDS=3`, `CONFIG=debug`): the pipeline's own time on the stop path, p50/p90/p99 in µs, in a release build. The interval starts as the stop tap's chord-down goes to `DictationPipeline.handle` (the stop begins there, not at the chord-up) and ends when `Paster.sendPaste` runs; the chord-up goes in at once after the chord-down. Every port is a test fake, so no network, mic, pasteboard or posted event is in it: it is not the latency gate. `BASE=main` exports main with `git archive` and runs it in turn with your checkout, so a before/after is one command. The test (`StopProbeTests`) runs only under this target; `make test` skips it. Round-to-round noise is about 0.5 µs at p50.
- `bench/`: provider benchmark (bun, TypeScript), see `bench/README.md`. Runs against paid APIs need the owner's explicit go.

## Module boundaries

- `KotobaCore/`: pure Swift package. `DictationPipeline` (actor) takes hotkey events and drives six ports: `AudioSource`, `TranscriptionProvider`, `Paster`, `Pasteboard`, `PipelineClock`, `Store`. Every decision lives here: tap vs hold, Esc, the 10-minute warning, retry queue, clipboard restore rules, latency marks. Imports Foundation, os and Synchronization only (lint-enforced).
- `App/`: AppKit app in the Dock and the menu bar (`LSUIElement` at launch; `DockAndMenuBar` owns the activation policy). Thin adapters that implement the ports with AVAudioEngine, CGEventTap, NSPasteboard, URLSession, SQLite and the Keychain, plus the indicator panel and on-demand windows.
- `spikes/`: throwaway experiments, outside `make check`.

## Rules

- **No patchwork** (owner, 2026-10-16): build the root design, not a fix on top of a fix. Code is performant by construction: event-driven (an observer or notification, never a polling timer where an event exists), no work at idle, no copies on the hot path. Each change reports its measured cost.
- **Licence**: copy code only from MIT or Apache-2.0 projects (Jot, Hex, FreeFlow). Keep their notice at the top of the copied file and add an entry to `NOTICE`. GPL projects (VoiceInk, TypeWhisper) are read-only references: take ideas, write your own code.
- **Event-driven hot path** (key-down to Cmd-V sent): each step waits on its event (first audio buffer, HTTP response, pasteboard change). A real timeout sleeps on the injected `PipelineClock`, so tests control it. A change to the stop path (from the stop tap to Cmd-V sent) reports `make stop-probe BASE=main` (main and the change, in turn; about 1 min).
- **One long-lived URLSession per provider**, created in the provider's init and warmed at key-down. Lint flags every `URLSession(`; that one line carries `// swiftlint:disable:next url_session_construction`.
- **Gates**: latency from stop tap to Cmd-V sent p50 <= 1.0 s and p90 <= 1.5 s; idle memory is measured with `footprint` (floor in `docs/research/memory-spike.md`). A change that adds work to the hot path or loads a framework at launch reports its measured cost.
- **Test-first through the seam**: hotkey events in, assertions on the fakes out. `KotobaCore/Tests/KotobaCoreTests/PipelineHotkeyTests.swift` shows the style.
- **Signing**: every build uses the Developer ID in `project.yml` (team 7U6G55576W), so TCC grants and Keychain access survive rebuilds. The keychain holds another team's identity; keep the full identity name.
- **Dev install** (owner, 2026-10-16): Debug builds (`make build`, `make check`, `make snapshots`) are "kotoba Dev", `tech.teensy.kotoba.dev`, with their own UserDefaults, data folder (`~/Library/Application Support/kotoba-dev/`), Keychain item, log subsystem, TCC grants and login item, so they never touch the owner's release install. Every such name comes from the bundle id (`App/Install.swift`, `Log.subsystem` in the packages; lint and `scripts/check-dev-install.sh` guard it). The owner grants Microphone and Accessibility to kotoba Dev once and saves its own API key in it. While the release app runs, kotoba Dev turns its hotkey tap off (`InstallYield`), so one chord never dictates twice.
- **Permissions**: the owner clicks Allow on every TCC prompt. Stop and ask when a prompt blocks you.
- **Long commands** (lead, 2026-10-16): run builds, `make check`, `make snapshots`, tests and bench passes in the foreground (Bash timeout up to 600000 ms). A background run's exit notice did not wake agents several times; an agent that ends its turn to wait on its own run stalls.
- **Processes**: stop only the PIDs you started. Never `pkill`/`killall` by name: `kotoba` also matches the owner's app and other agents' `--snapshots` runs. UI scripting (AppleScript, System Events, accessibility tools) targets a PID you started, never a bundle id or app name: by bundle id it drives the owner's running app.
- **No synthetic input** (owner, 2026-10-16): never post mouse or keyboard events (CGEvent post, HID clicks, cliclick, computer-use or cmux-cua tools, System Events `click`/`keystroke`). They move the owner's real pointer and type into the owner's apps. Check UI with `make snapshots` and unit tests; read focus and activation from `log stream`/`log show`. When only a real click can prove a fix, write the steps and ask the lead for an owner trial.
- **Nothing on screen** (2026-10-25): snapshot and probe code never orders a window in (`orderFront`, `orderBack`, `makeKeyAndOrderFront`), at any position, not even off screen or at alpha 0: AppKit moves the window, or the sheet it presents, onto the owner's screen. Capture only windows that are never ordered in (ScreenCaptureKit `desktopIndependentWindow`). A sheet needs a parent on screen, so sheet images show the content only (`MainWindow.sheetSnapshot`); what needs an on-screen window becomes owner-trial steps.
- **Safety hook**: when the Safety Net hook blocks a git or file command, do not reach the same result another way (stash, update-ref, a temporary branch). Stop and ask the lead. To squash or reword your own unpushed commits, use a soft reset, `git commit --amend` or `git rebase`.
- **Migrations**: a schema migration starts only from a shape that shipped (a pushed `main` or a release tag). While your feature is unpushed, change its migration in place; never add a step that converts your own unpushed schema. The history's indexes are one list (`HistoryStore.indexes`), which each open makes the database match: to change an index, change its entry; no rename and no drop step.
- **Shared checkout**: several agents can work in this checkout at once. Test targets must always compile: a new test fails by assertion, with stub sources, never by a missing type. Edit only the files your task owns; to change a file another agent owns, message that agent with the interface you need. The app build must stay green between your edits too: other agents block on it for snapshots and `make check`. Write a new type so it compiles at each save (stub bodies first, then fill in), and build right after each edit (`swift build --package-path <pkg>` for a package, `make build-check AGENT=<you>` for App/). If you break it, fixing it comes before anything else.

Code style and patterns: `CODING_STANDARDS.md`.
